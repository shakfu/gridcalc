# Performance review, 2026-11-10

Measured on gridcalc 0.13.0, EXCEL mode, `GRIDCALC_SANDBOX=1`. No code changed.
Earlier figures: `docs/dev/ironcalc.md`, `docs/dev/comparison.md`, TODO > Performance.

## 1. Array `IF`, `IFERROR` and `IFNA` are quadratic

`_element` (`src/gridcalc/formula/evaluator.py:1329`) runs `list(v.data)` on every call.
`_choose` (`:1350`) and `_replace_where` (`:1363`) call it once per element of the
condition. Each element read copies the whole branch array.

| rows | `SUM(IF(B>3,B,0))` | `SUM(IFERROR(1/(B-3),B))` |
|-|-|-|
| 2,500 | 31 ms | 7 ms |
| 10,000 | 243 ms | 61 ms |
| 40,000 | 3,727 ms | 1,144 ms |

Each 4x in rows costs about 16x in time. Element-wise arithmetic over the same
range stays at 0.5-1.4 us per element:

| formula, 10,000 rows | us per element |
|-|-|
| `SUM(B*2)` | 0.52 |
| `SUM((B=3)*1)` | 0.76 |
| `SUM(ROW(B)-ROW(B1)+1/(B=3))` | 1.39 |
| `SUM(IF(B>3,B,0))` | 10.8 |

Fix: read each branch's data once, before the loop. About 5 lines.
Expected after the fix: about 1 us per element (estimate, not measured).

TODO says `IF` over Vecs dominates the profile of Sheetpedia `846882d...`, which
reaches the 30 s limit. This fix may resolve it. Not confirmed.

## 2. Each recalc rebuilds the closure and its order

Model: `scripts/named_io_bench.py` at 10 blocks, 18,033 formulas, inputs `Rate`
and `Principal`. A case in `Book.run_many` takes 90-95 ms. `comparison.md`
recorded 173 ms; runs vary.

Of each case, 32-38 ms is the BFS over `_subscribers` and the Kahn ordering in
`_recalc_topo` (`src/gridcalc/engine.py:4368-4420`). Every case dirties the same
2 cells, so each rebuilds the same 18,043-node order.

Fix: cache the closure, the order and the stuck (cycle) cells, keyed on a graph
version and the dirty set.

- Bump the version in `_clear_deps`, `_register_deps` and
  `_rebuild_dep_graph` (`engine.py:3293-3356`). grep finds no other writer of
  `_dep_of`, `_subscribers`, `_ranges` or `_volatile`.
- Key also on which dirty cells hold formulas. A formula with no reference,
  such as `=1+1`, adds no edge but joins the closure.
- Expected: about 1.6x per case for sweeps and repeat edits of one cell. A first
  recalc gains nothing.
- Risk: a graph change that skips the version bump gives stale order and wrong
  values. Test insert, delete, rename and undo with the cache warm.

## 3. Smaller per-formula costs

Shares are from cProfile, which inflates timings about 4x.

- `_store_formula_result` (`engine.py:3980`) runs an import on every call:
  379k lookups in 21 recalcs, about 2%.
- A cell read takes 4 Python calls: `get_cell`, `lookup`, `demand`,
  `_cell_lookup_value`. With no volatile cell in the closure, `demand` always
  returns True, so `env.cell_value` can bind `_cell_lookup_value` directly.
  About 4%.

With items 2 and 3 a case would take about 50 ms, against GridCraft's 26 ms.
The rest is the evaluator's tree walk and Python call cost. TODO > Low >
Performance ("C++ is not justified") covers that.

## 4. Deferred: vectorised element-wise operators

Sheetpedia `802559d...` (7,676 `AGGREGATE` formulas over 10,000 rows, 232 s)
needs about 0.05 us per element or less. Only numpy reaches that. numpy is an
optional extra and the core has no third-party dependencies, so this means two
code paths. It costs more than items 1-3 and helps 1 file in the corpus.

## Recommendation

1. Fix item 1 first, whatever the product direction. It affects any array
   formula over a large range. The gap to GridCraft matters only for sweeps.
2. Do item 2 if batch runs or editor response on large models matter.
3. Do item 3 alongside item 2; both touch `_recalc_topo`.
4. Leave item 4 until a workload other than `802559d...` needs it.

## Results, items 1 and 2

Implemented the same day.

| | before | after |
|-|-|-|
| `SUM(IF(B>3,B,0))`, 40,000 rows | 3,727 ms | 34 ms |
| `SUM(IFERROR(1/(B-3),B))`, 40,000 rows | 1,144 ms | 34 ms |
| named-input case, 18,033 formulas | 90-95 ms | 63 ms |

- Array `IF` and `IFERROR` now cost 0.84-1.02 us per element at 2,500,
  10,000 and 40,000 rows.
- Sheetpedia `846882d...`: load and recalc 21.3 s before, 17.1 s after, no
  `#CALC!` in either. Item 1 gave 20%, not the fix the profile suggested.
- The order cache holds up to 8 dirty sets. Any write to the graph empties it.
- IronCalc and pycel corpus: 78,942 of 79,661 cells before and after, with no
  file changed.
- Tests: `tests/test_topo_cache.py`, and
  `test_an_array_branch_is_read_once_not_once_per_element` in
  `tests/test_formula_integration.py`. Each fails if its fix is removed.
